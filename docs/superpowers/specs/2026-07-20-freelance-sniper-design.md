# Рабочий раздел «Фриланс» и локальный снайпер заказов

Дата: 20 июля 2026 года

## Цель

Заменить демонстрационный раздел «Фриланс» полноценным локальным CRM-модулем. Модуль хранит реальные заказы, собирает новые заказы с выбранных площадок, исключает дубли, позволяет вести статусы и отправляет отдельное Telegram-уведомление на каждый новый подходящий заказ.

Снайпер работает только пока запущен локальный backend Semix CRM. После остановки CRM мониторинг прекращается.

## Источники

Поддерживаются шесть независимо включаемых источников:

- Kwork;
- FL.ru;
- Freelance.ru;
- Workzilla;
- Profi.ru;
- YouDo.

Для каждого источника используется отдельный адаптер с общим контрактом. Способ получения данных выбирается по возможностям площадки:

- официальный API — когда он доступен и подходит для чтения проектов;
- HTTP и разбор публичной ленты — для общедоступных страниц;
- Chromium с постоянным локальным профилем — для персональных лент после авторизации.

CRM не обходит CAPTCHA, ограничения доступа и защиту площадок. Если источник требует повторного входа или ручного подтверждения, он переходит в состояние `auth_required`, остальные источники продолжают работать.

## Архитектура

Backend содержит следующие изолированные компоненты:

1. `FreelanceAdapter` — общий контракт получения заказов.
2. Адаптеры шести площадок — преобразуют внешние данные в единый формат.
3. `FreelanceService` — применяет фильтры, нормализует данные и сохраняет только новые заказы.
4. `FreelanceSniper` — локальный фоновый цикл, запускаемый и останавливаемый через API.
5. `TelegramNotifier` — отправляет сообщение только настроенному разрешённому получателю.
6. SQLite-репозиторий — хранит заказы, настройки, проверки источников и факты отправки уведомлений.

Ошибка одного адаптера не останавливает общий цикл. Результат каждой проверки фиксируется отдельно по источнику.

## Единая модель заказа

Каждый заказ содержит:

- внутренний ID;
- источник;
- внешний ID;
- название;
- описание;
- категории и технологии;
- исходную ссылку;
- имя или идентификатор заказчика, если он публично доступен;
- минимальный и максимальный бюджет;
- валюту;
- исходный текст бюджета;
- дату публикации;
- дату первого обнаружения;
- рассчитанную релевантность;
- статус CRM;
- следующий шаг;
- пользовательскую заметку;
- признак скрытого заказа.

Отсутствующие внешние поля остаются пустыми. Backend не создаёт вымышленные значения.

## Дедупликация

Основной ключ дубля — комбинация `source + external_id`. Если внешний ID недоступен, используется нормализованная исходная ссылка. Последний резервный ключ строится из источника, нормализованного заголовка и даты публикации.

Отдельная таблица фактов Telegram-отправки гарантирует, что заказ не будет повторно отправлен после перезапуска CRM.

## Статусы CRM

Поддерживаются статусы:

- `Новый`;
- `Написал`;
- `Откликнулся`;
- `Ответили`;
- `Созвон`;
- `В работе`;
- `Завершён`;
- `Отказ`.

Статус и следующий шаг изменяются пользователем и сохраняются в SQLite.

## Настройки снайпера

Настройки включают:

- выбранные источники;
- ключевые слова;
- исключающие слова;
- минимальный бюджет;
- категории;
- интервал проверки;
- состояние снайпера;
- состояние Telegram-уведомлений;
- разрешённый Telegram chat ID;
- состояние авторизации каждого источника.

Минимальный безопасный интервал ограничивается backend. Для источников может применяться небольшой разброс времени проверки, чтобы не отправлять одновременные запросы ко всем площадкам.

## Авторизация в браузере

Для закрытых площадок используется отдельный локальный профиль Chromium в каталоге данных backend. Пользователь нажимает «Открыть вход», самостоятельно авторизуется на площадке и закрывает окно после успешного входа.

Логины, пароли и cookies не записываются в исходный код и не отправляются в Git. Cookies остаются в локальном профиле Chromium.

## Telegram

Токен Telegram-бота берётся только из переменной окружения `TELEGRAM_BOT_TOKEN`. Разрешённый получатель задаётся переменной `TELEGRAM_ALLOWED_CHAT_ID` и дополнительно отображается в настройках только в маскированном виде.

Ранее опубликованный токен не используется и должен быть перевыпущен владельцем через BotFather.

Каждый новый подходящий заказ отправляется отдельным сообщением со следующими данными:

- площадка;
- название;
- бюджет;
- дата публикации;
- краткое описание;
- рассчитанная релевантность;
- исходная ссылка.

Ошибка Telegram не удаляет заказ и не останавливает снайпер. Неотправленный факт сохраняется с ошибкой и может быть повторно отправлен после исправления настроек.

## API

Backend предоставляет:

- получение списка заказов и статистики;
- создание ручного заказа;
- обновление статуса, следующего шага и заметки;
- скрытие заказа;
- получение и сохранение настроек снайпера;
- запуск и остановку снайпера;
- однократную ручную проверку выбранных источников;
- получение состояния источников;
- открытие авторизационного окна для выбранного браузерного источника;
- получение истории проверок.

Операции возвращают понятные состояния `loading`, `done`, `partial`, `auth_required` и `error` без подмены реальных результатов демонстрационными данными.

## Интерфейс

Текущая страница сохраняет общий стиль Semix CRM и тёмную тему, но получает данные только через API.

Основная колонка содержит:

- реальные метрики из базы;
- поиск;
- фильтры источника, статуса, категории и бюджета;
- сортировку по дате, бюджету и релевантности;
- кнопку ручного добавления заказа;
- карточки с бюджетом, источником, датой, ссылкой, статусом, следующим шагом и заметкой;
- честные состояния загрузки, пустой базы и ошибки.

Боковая колонка содержит:

- включение и остановку снайпера;
- кнопку однократной проверки;
- выбранные источники и фильтры;
- состояния авторизации и последней проверки;
- рекомендации, рассчитанные только по сохранённым заказам;
- реальные этапы заказов;
- последние ошибки и история проверок.

Настройки открываются в доступном модальном окне с видимыми подписями, управлением с клавиатуры и понятной обратной связью.

## Релевантность

Первая версия использует объяснимую балльную модель без внешней нейросети:

- совпадения ключевых слов в названии имеют больший вес;
- совпадения в описании и категориях имеют меньший вес;
- бюджет выше заданного минимума повышает оценку;
- исключающие слова исключают заказ;
- отсутствующий бюджет не считается нулевым и не ухудшает оценку автоматически.

На карточке показывается процент и причины оценки.

## Обработка ошибок

- Ошибка одного источника изолируется и отображается рядом с ним.
- Истёкшая сессия переводит источник в `auth_required`.
- CAPTCHA не обходится; пользователь получает инструкцию открыть окно входа.
- Сетевой таймаут не удаляет ранее сохранённые заказы.
- Ошибка разбора страницы фиксируется в истории с диагностикой.
- Ошибка Telegram сохраняется отдельно и не создаёт повторный заказ.
- Пустой ответ источника отображается как нулевой результат, а не заполняется тестовыми заказами.

## Тестирование

Разработка выполняется через TDD.

Автоматические тесты покрывают:

- создание и изменение заказов;
- статистику и фильтрацию;
- дедупликацию с внешним ID, ссылкой и резервным ключом;
- сохранение настроек;
- расчёт релевантности;
- запуск, остановку и повторный запуск снайпера;
- изоляцию ошибок источников;
- единственного разрешённого Telegram-получателя;
- отсутствие повторных уведомлений;
- адаптеры на сохранённых API/HTML fixtures;
- API-контракты.

Ручная браузерная проверка включает создание заказа, изменение статуса, сохранение после перезагрузки, фильтры, настройку источников, запуск и остановку снайпера, пустые состояния, светлую и тёмную темы, отсутствие горизонтального переполнения и ошибок консоли.

Live-проверка источников проводится только с реальными страницами и авторизованными сессиями пользователя. Тестовые результаты не сохраняются в рабочую базу.

## Границы первой версии

В первую версию не входят:

- автоматическая отправка откликов;
- обход CAPTCHA;
- хранение паролей площадок;
- круглосуточная работа после выключения CRM или компьютера;
- облачный сервер;
- нейросетевая генерация текста отклика;
- финансовый учёт договоров и выплат.

Эти функции могут быть спроектированы отдельно после стабилизации сбора заказов.
