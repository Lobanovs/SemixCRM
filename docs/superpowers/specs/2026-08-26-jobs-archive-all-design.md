# Массовое архивирование вакансий

## Цель

Добавить в раздел «Работа (вакансии)» безопасное действие «Все в архив», которое одним запросом переносит все активные вакансии в существующий архив без удаления данных.

## Поведение интерфейса

- Кнопка «Все в архив» находится в панели управления активным списком рядом с переходом в архив.
- В режиме просмотра архива массовое действие не показывается.
- Кнопка недоступна, если активных вакансий нет или операция уже выполняется.
- Перед выполнением браузер показывает подтверждение с точным количеством активных вакансий.
- Во время запроса подпись меняется на «Архивирую…», повторное нажатие невозможно.
- После успеха список и статистика загружаются заново, а пользователь видит сообщение с фактическим количеством перенесённых вакансий.
- При отказе от подтверждения запрос не выполняется; при ошибке данные на экране сохраняются и показывается понятное сообщение.

## API и данные

- Новый защищённый маршрут `POST /api/jobs/archive-all` вызывает одну операцию хранилища.
- Хранилище одной SQL-командой устанавливает `archived = 1` и обновляет `updated_at` только у записей с `archived = 0`.
- Ответ содержит `ok: true` и `archived_count` с фактическим числом изменённых строк.
- Повторный вызов идемпотентен и возвращает `archived_count: 0`.
- Маршрут объявляется до параметризованного `/api/jobs/{job_id}`, чтобы `archive-all` не разбирался как идентификатор.

## Проверка

- Backend-тест проверяет перенос всех активных вакансий, сохранение уже архивных записей и повторный вызов.
- Frontend-тест проверяет подтверждение, защищённый POST-запрос, состояние загрузки и обновление списка.
- Отдельный frontend-тест подтверждает, что отмена диалога не отправляет запрос.
- После реализации запускаются профильные тесты, полный набор тестов, production-сборка и ручная проверка в браузере.
