# «Полезные вещи»: дизайн раздела

## Цель

Добавить в Semix CRM отдельный desktop-раздел для хранения полезных рабочих сайтов.
Пользователь должен видеть понятный каталог, быстро находить нужный ресурс и выполнять
полный CRUD без перехода в настройки или редактирования файлов.

## Выбранный подход

Данные хранятся в SQLite через новый REST API. Это надёжнее `localStorage`: каталог
остаётся частью общей базы CRM, одинаково работает после перезапуска браузера и
проверяется backend-тестами.

Большая база знаний с тегами, категориями, заметками и вложениями сейчас не нужна.
Первая версия хранит только то, что прямо требуется:

- название сайта;
- URL;
- описание;
- даты создания и последнего изменения.

## Навигация

В левом меню появляется вкладка «Полезные вещи» с outline-иконкой закладки из Lucide.
Она также появляется в «Быстром доступе» на главной. Переключение остаётся внутри
существующей SPA без перезагрузки.

## Интерфейс

Страница следует текущей плотной desktop-системе Semix CRM:

- заголовок и короткое объяснение назначения;
- счётчик сохранённых сайтов;
- локальный поиск по названию, домену и описанию;
- основная кнопка «Добавить сайт»;
- адаптивная сетка карточек;
- полезное пустое состояние с кнопкой добавления;
- отдельное состояние «ничего не найдено» с очисткой поиска.

Карточка показывает название, нормализованный домен, описание и три явных действия:
«Открыть», «Изменить», «Удалить». Ссылка открывается в новой вкладке с
`rel="noreferrer"`. Вся карточка не становится ссылкой, чтобы исключить случайный
переход во время редактирования.

Добавление и редактирование используют одну модальную форму с видимыми подписями:

- «Название» — обязательно, максимум 120 символов;
- «Адрес сайта» — обязательно, максимум 2048 символов;
- «Описание» — необязательно, максимум 1000 символов.

Если схема URL не указана, backend добавляет `https://`. Разрешены только `http` и
`https` с реальным именем хоста. Повторный URL отклоняется понятным сообщением.
Ошибки показываются с `role="alert"`, успешные операции — с `role="status"`.

Удаление требует отдельного подтверждения с названием сайта. После успешной операции
карточка исчезает без полной перезагрузки страницы.

## API и хранение

SQLite-таблица `useful_links`:

```text
id INTEGER PRIMARY KEY AUTOINCREMENT
title TEXT NOT NULL
url TEXT NOT NULL UNIQUE
description TEXT NOT NULL DEFAULT ''
created_at TEXT NOT NULL
updated_at TEXT NOT NULL
```

REST-контракт:

- `GET /api/useful-links` → `{items, stats: {total}}`;
- `POST /api/useful-links` → созданный ресурс, HTTP 201;
- `PUT /api/useful-links/{id}` → обновлённый ресурс;
- `DELETE /api/useful-links/{id}` → `{ok, deleted_id}`.

Изменяющие запросы используют существующий заголовок `X-Requested-With: SemixCRM`.
Отсутствующая запись возвращает 404, некорректный URL — 422, дубликат — 409.

## Проверка

Backend-тесты покрывают нормализацию URL, сортировку, полный CRUD, валидацию,
дубликаты и 404. Frontend-тесты покрывают загрузку, поиск, добавление, изменение,
подтверждение удаления, ошибки и заголовок безопасного запроса. Навигационный тест
подтверждает открытие новой вкладки.

Перед доставкой выполняются полный frontend-набор, полный backend-набор,
production-сборка, `git diff --check` и ручная проверка локального API/страницы.
